Part A: Exploring the Power of Flow Models

Overview

Everything in Part A is a sampling procedure built on the model's velocity prediction $\hat v_\theta(x_t, t, c)$. Flow matching uses the linear interpolation $x_t = (1-t)\,\epsilon + t\,x_1$ with $\epsilon \sim \mathcal{N}(0, I)$, so $t=0$ is pure noise and $t=1$ is the clean image, and the model is trained to predict the path velocity $v = x_1 - \epsilon$. All results use seed 180, Euler step size $h = 0.02$ and, where guidance is used, CFG weight $w = 7$. For Sections 1.1–1.5 I used my own image, center-cropped and resized to 512×512.

A 1.1 · Constructing Noisy Training Inputs

interpolate(image, noise, t) scales the image by $t$ and the noise by $1-t$, so this is not just adding noise. One noise tensor is sampled and reused for $t = 0.25, 0.50, 0.75$, so only $t$ changes between the images. I checked both endpoints: $t=0$ returns exactly the noise and $t=1$ returns exactly the image.

$$x_t = (1-t)\,\epsilon + t\,x_1,\quad \epsilon \sim \mathcal{N}(0, I)$$

At $t=0.25$ the image is almost entirely noise: only a faint outline of the cat's head and a warm orange tint hint at what is underneath. At $t=0.50$ the cat's face, the window slats, and the overall colors are clearly visible through heavy grain, and at $t=0.75$ the picture is close to the original, with only light grain left that is most visible in smooth regions like the floor.

click to show interpolate() code 
def interpolate(image, noise, t):
    return (1 - t) * noise + t * image

A 1.2 · Classical Denoising

As a baseline with no learned model, I blur the noisy image. The image part of $x_t$ is scaled by $t$, so I first divide by $t$ to restore its amplitude (this does not remove noise; it amplifies it) and then apply a Gaussian filter $G_\sigma$. For each time I swept $\sigma \in \{1, 2, 4, 8, 16\}$ and kept the $\sigma$ with the lowest MSE against the clean image, so this baseline is a best case that peeks at the ground truth.

$$\hat x_1 = G_\sigma * (x_t / t)$$

A stronger blur averages away more noise but also erases more detail, so the best $\sigma$ rises as $t$ falls: $\sigma=2$ at $t=0.75$, $4$ at $t=0.50$, and $8$ at $t=0.25$. At $t=0.75$ the light blur keeps the cat's eyes and fur with only slight softening. At $t=0.50$ the cat is recognizable but soft, and blotchy color noise survives because blurring cannot remove noise that is correlated over several pixels. At $t=0.25$ even $\sigma=8$ recovers only the broad layout and colors, since the fine detail is gone, so this baseline cannot get anywhere near the original.

A 1.3 · One-Step Denoising

The model predicts a velocity, not noise, so one prediction extrapolates from $t$ to the clean endpoint. I also checked that the velocity has the same shape, dtype and device as the input.

$$\hat x_1 = x_t + (1-t)\,\hat v_\theta(x_t, t, c)$$

One step does far better than blur at every noise level. At $t=0.75$ and $t=0.50$ the estimate is close to the original, with the cat's face, whiskers, and background shapes restored, because the model uses what it has learned about images instead of just averaging pixels. The estimate is a little smoother than the original, with fur and floor texture softened, since a single prediction can only give an average of plausible images. This is strongest at $t=0.25$, where the overall layout is right but fine detail is smeared.

click to show one_step_denoise() code 
def one_step_denoise(x, t, condition, predict_velocity):
    with torch.no_grad():
        v = predict_velocity(x, t, condition)
    return x + (1 - t) * v

A 1.4 · Visualizing Velocity

Here I look at what the model adds in the one-step estimate and compare it with what should be added. The ground-truth velocity is $v_{gt} = x_1 - \epsilon$, so its update is $(1-t)v_{gt} = x_1 - x_t$. The error map is the per-pixel RMS difference of the two updates, averaged over RGB. Predicted and ground-truth updates share one symmetric RGB scale (zero is mid-gray), and the error maps share one color scale across all three times.

$$E_t = \sqrt{\operatorname{mean}_{RGB}\Big(\big[(1-t)(\hat v_t - v_{gt})\big]^2\Big)}$$

Each row: noisy image, predicted update $(1-t)\hat v$, ground-truth update $(1-t)v_{gt}$, RMS error heatmap.

The predicted update has the same broad structure as the ground-truth update (the cat's outline, the window, and the dark and light regions show up in both), but the ground truth also contains the exact noise pattern, which the model cannot know. The error maps therefore light up along edges and fine texture, such as the cat's silhouette, its fur, and the window slats, and stay near zero in smooth regions. All three maps share one color scale, and the error shrinks as $t$ grows. Part of that is just because both updates are scaled by $(1-t)$, so there is less left to add.

click to show velocity_diagnostics() code 
@torch.inference_mode()
def velocity_diagnostics(x_t, t, clean_image, epsilon, condition, predict_velocity):
    v_hat = predict_velocity(x_t, t, condition)
    predicted_update = (1 - t) * v_hat
    ground_truth_update = (1 - t) * (clean_image - epsilon)   # = clean_image - x_t
    error_map = ((predicted_update - ground_truth_update) ** 2).mean(dim=1).sqrt()
    return predicted_update, ground_truth_update, error_map

A 1.5 · Iterative Denoising with Euler Sampling

One-step denoising is inaccurate because the learned velocity changes along the path. Instead I take small steps and recompute the velocity after each one. Starting from the saved $t = 0.50$ noisy image, 25 Euler updates of $h = 0.02$ reach $t = 1$; the last step is shortened if needed to end exactly at 1. I tested the sampler on constant velocity fields (50 steps from 0, 25 from 0.5, and a shortened final step from 0.93).

$$x_{t+h} = x_t + h\,\hat v_\theta(x_t, t, c)$$

Blur is clearly the worst: it is noisy and soft at once. One-step and Euler both land close to the original. Lower MSE does not necessarily mean better looking, though. A one-step estimate is a smooth average over plausible images, which scores well on pixel error, while Euler commits to a single sharp, realistic sample whose small details can differ from the original and cost some MSE. In the trajectory the state is still grainy from $t=0.50$ to $0.70$, the noise clears between $0.70$ and $0.80$, and the remaining steps refine texture and color.

click to show euler_sample() code 
@torch.inference_mode()
def euler_sample(x_start, t_start, step_size, velocity):
    x = x_start.clone()
    t = float(t_start)
    states = [(t, x.clone())]
    k = 0
    while t < 1 - 1e-8:
        h = min(step_size, 1 - t)
        x = x + h * velocity(x, t)
        t = t + h
        if abs(1 - t) < 1e-8:
            t = 1.0
        k += 1
        if k % 5 == 0 or t == 1.0:
            states.append((t, x.clone()))
    return x, states

A 1.6 · Generating Images from Noise

Setting $t_{start}=0$ and passing pure noise to euler_sample generates images from scratch. Five samples with the prompt a high quality photo, seeds 180–184.

All five samples are people: close-up portraits and torsos. The generic prompt "a high quality photo" clearly pulls the model toward portrait photography. Quality is uneven without guidance. Seed 180 turns the face away and loses it, seed 183 has a distorted, weathered face, seed 181 has strange skin texture on the torso, and seed 182 is awkwardly cropped around a raised hand. Only seed 184 reads as a normal photo of a man.

A 2.1 · Classifier-Free Guidance

To improve prompt alignment and image quality at the expense of diversity, I evaluate the same $x_t$ and $t$ with the conditional prompt and with the empty prompt, then extrapolate from the unconditional prediction toward the conditional one. With $w = 0$ this reduces exactly to the conditional prediction (verified in code). I use $w = 7$ and $h = 0.02$, with the same initial noises as A 1.6.

$$v_{cfg} = v_c + w\,(v_c - v_u),\quad w = 7$$

Guidance makes a big difference. With $w=7$ every sample is a sharp, well-formed, frontal portrait with a recognizable face, clean lighting, and a plausible shirt, which fixes the failures in A 1.6 (the missing face in seed 180 and the distorted face in seed 183). The cost is diversity: the unguided samples varied in framing, crop, and even whether a face was visible, but all five guided images are centered head-and-shoulders portraits with similar studio-style lighting and plain backgrounds. Each seed keeps some of its earlier character (the raised hand in seed 182 appears in both versions), so guidance sharpens what the noise already suggested instead of replacing it. The subject is still "a portrait of a person" either way; guidance just makes the model more confident in that reading.

click to show cfg_velocity() code 
def cfg_velocity(x, t, condition, w, predict_velocity, null_condition=''):
    if isinstance(null_condition, str):
        null_condition = model.encode(null_condition)
    v_c = predict_velocity(x, t, condition)        # same x and t for both branches
    v_u = predict_velocity(x, t, null_condition)
    return v_c + w * (v_c - v_u)

A 3.1 · Image-to-Image Editing

SDEdit-style editing: noise an image to time $t_{start}$ with the forward process, then denoise with CFG ($w = 7$, $h = 0.02$) from $t_{start}$ to 1 using the prompt a high quality photo. Starting times run from most noise (left) to least (right): $t_{start} \in \{0.02, 0.04, 0.06, 0.10, 0.14, 0.25, 0.50\}$. The denoising forces the noisy image back onto the manifold of natural images, so lower $t_{start}$ means a bigger edit.

click to show edit() code 
def edit(image, noise, t_start, condition, predict_velocity, w=7, step_size=0.02):
    x = interpolate(image, noise, t_start)
    null = model.encode("")
    guided = lambda x, t: cfg_velocity(x, t, condition, w, predict_velocity, null)
    out, _ = euler_sample(x, t_start, step_size, guided)
    return out

A 3.3 · Visual Anagrams

A visual anagram is one image that reads as two different things when flipped upside down. At each step I compute the CFG velocity of the image with prompt $c_a$, rotate the image by 180° (both spatial axes), compute the CFG velocity with prompt $c_b$, rotate that velocity back, and average the two. The averaged velocity drives the Euler update from pure noise.

$$v = \tfrac{1}{2}\Big[v_{cfg}(x_t, t, c_a) + F\big(v_{cfg}(F(x_t), t, c_b)\big)\Big],\quad F = \text{rotate } 180^\circ$$

click to show visual_anagrams() code 
def visual_anagrams(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
    null = model.encode("")
    def v(x, t):
        v_a = cfg_velocity(x, t, condition_a, w, predict_velocity, null)
        v_b = rotate180(cfg_velocity(rotate180(x), t, condition_b, w, predict_velocity, null))
        return (v_a + v_b) / 2
    out, _ = euler_sample(noise, 0, step_size, v)
    return out

A 3.4 · Hybrid Images

Following Factorized Diffusion, I predict a CFG velocity with each of two prompts, then keep the low frequencies of the first and the high frequencies of the second. The low-pass is a Gaussian blur with kernel size 265 and $\sigma = 16$ at 512×512, and the high-pass is the prediction minus its low-pass. The distant (low-frequency) prompt shows when the image is small or far away; the close (high-frequency) prompt shows at full size.

$$v = \operatorname{lowpass}(v_a) + v_b - \operatorname{lowpass}(v_b)$$

click to show make_hybrids() code 
def make_hybrids(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
    null = model.encode("")
    def v(x, t):
        v_a = cfg_velocity(x, t, condition_a, w, predict_velocity, null)
        v_b = cfg_velocity(x, t, condition_b, w, predict_velocity, null)
        return lowpass(v_a) + v_b - lowpass(v_b)
    out, _ = euler_sample(noise, 0, step_size, v)
    return out

Part B: Flow Matching from Scratch

Overview

In Part B I train my own models on MNIST. I first build a one-step denoising UNet and see why it fails as a generator. Then I train a UNet to predict the flow from noise to data and sample by iterative Euler integration, first conditioned on time only, then on time and digit class with classifier-free guidance.

B 1.1 · Implementing the UNet

The UNet follows the assignment diagram. Two downsampling blocks take the $28\times28$ input to $7\times7$, a pooled $1\times1$ bottleneck is unflattened back to $7\times7$, and skip connections are concatenated at each resolution. $D$ is the hidden width: 128 for the single-step denoiser and 64 for the flow-matching models.

Operations

  • Conv: Conv2d(3, 1, 1) + BatchNorm + GELU (changes channels only).
  • DownConv: Conv2d(3, 2, 1) + BatchNorm + GELU (halves resolution).
  • UpConv: ConvTranspose2d(4, 2, 1) + BatchNorm + GELU (doubles resolution).
  • Flatten: AvgPool(7) + GELU ($7\times7 \to 1\times1$).
  • Unflatten: ConvTranspose2d(7, 7, 0) + BatchNorm + GELU ($1\times1 \to 7\times7$).
  • ConvBlock / DownBlock / UpBlock: built from the ops above (two Convs; DownConv + ConvBlock; UpConv + ConvBlock).

Channel flow: $1\times28\times28 \to D\times28\times28 \to D\times14\times14 \to 2D\times7\times7 \to 2D\times1\times1$, then back up with concatenations ($4D$ at $7\times7$, $2D$ at $14\times14$ and $28\times28$) before a final Conv2d(3, 1, 1) to one channel.

click to show UnconditionalUNet code 
class UnconditionalUNet(nn.Module):
    def __init__(self, in_channels, num_hiddens):
        super().__init__()
        D = num_hiddens
        self.conv0 = ConvBlock(in_channels, D)
        self.down1 = DownBlock(D, D)
        self.down2 = DownBlock(D, 2 * D)
        self.flatten = Flatten()
        self.unflatten = Unflatten(2 * D)
        self.up1 = UpBlock(4 * D, D)
        self.up2 = UpBlock(2 * D, D)
        self.conv1 = ConvBlock(2 * D, D)
        self.out = nn.Conv2d(D, in_channels, 3, 1, 1)

    def forward(self, x):
        c0 = self.conv0(x)
        d1 = self.down1(c0)
        d2 = self.down2(d1)
        u = self.unflatten(self.flatten(d2))
        u = self.up1(torch.cat([u, d2], dim=1))
        u = self.up2(torch.cat([u, d1], dim=1))
        u = self.conv1(torch.cat([u, c0], dim=1))
        return self.out(u)

B 1.2 · The Noising Process

To train a denoiser, each clean MNIST digit $x$ (pixels in $[0,1]$) is noised as below. Each row adds a different $\sigma$ to the same digits with one fixed noise tensor, so only the scale changes.

$$z = x + \sigma\epsilon,\quad \epsilon \sim \mathcal{N}(0, I)$$

The digit is easy to read up to about $\sigma=0.4$ to $0.5$, but by $0.6$ the stroke is mixed with noise of similar brightness, and at $0.8$ it is hard to pick out. At $\sigma=1.0$ only faint traces of the stroke remain.

B 1.2.1 · Training a Denoiser

I train the unconditional UNet to map a noisy digit back to its clean version with an L2 loss. Fresh noise is drawn for every batch, so the network never sees the same noisy image twice.

$$L = \mathbb{E}_{z,x}\,\lVert D_\theta(z) - x\rVert^2,\quad z = x + 0.5\,\epsilon$$

B 1.2.2 · Out-of-Distribution Testing

The denoiser was trained only at $\sigma = 0.5$. Here I apply the trained model to the same test digit with other noise levels, reusing one noise tensor so only $\sigma$ changes.

The denoiser handles lower noise and moderately higher noise well: the 7 comes out clean for $\sigma=0$ through $0.6$, including $\sigma=0$ and $0.2$, where the input has less noise than anything it trained on. It starts to fail at $\sigma=0.8$, where stray strokes and smudges appear around the 7, and by $\sigma=1.0$ the output is an invented squiggle that no longer looks like a 7. Since training used only $\sigma=0.5$, the model has not learned how to handle noise far beyond that level.

B 1.2.3 · Denoising Pure Noise

To turn denoising into generation, I train a fresh UNet with the same settings ($D = 128$, batch 256, lr $10^{-4}$, 5 epochs) but feed it pure Gaussian noise $z \sim \mathcal{N}(0, I)$ with a clean digit as the target.

What I observe, and why

Every noise input produces essentially the same output: a blurry, centered blob that looks like several digits overlaid. It is not any particular digit and barely depends on the input. This happens because the input noise is independent of the target digit, so it carries no information about which digit to produce. Under an MSE loss the best the network can do is output the single image that minimizes the summed squared distance to all training images, which is their mean (the centroid of the training set). The blob is bright in the center, where many digits have strokes, and dark at the edges, where almost none do. A single denoising step from noise therefore collapses the data distribution to its average, which is why Part 2 denoises iteratively.

B 2.1-2.2 · Time-Conditioned Flow Matching: Training

The UNet now predicts the flow $x_1 - x_0$ at an interpolated point $x_t$. Time is injected with two FCBlocks (Linear, GELU, Linear) that turn the scalar $t \in [0,1]$ into per-channel multipliers: the first scales the unflattened $7\times7$ features ($2D$ channels) and the second scales the output of the first up block ($D$ channels). A new noise tensor and new times are drawn for every batch.

$$x_t = (1-t)\,x_0 + t\,x_1,\quad x_0 \sim \mathcal{N}(0, I),\ t \sim U[0,1]$$ $$L = \mathbb{E}\,\lVert (x_1 - x_0) - u_\theta(x_t, t)\rVert^2$$

    t = torch.rand(x_1.shape[0], device=x_1.device)
    x_0 = torch.randn_like(x_1)
    tt = t.view(-1, 1, 1, 1)
    x_t = (1 - tt) * x_0 + tt * x_1

B 2.3 · Sampling from the Time-Conditioned UNet

Sampling starts from pure noise $x_0$ and integrates the learned flow with Euler steps from $t = 0$ to 1. Each figure uses the same seed and starting noise, so differences between epochs come only from the weights.

$$x_{t+h} = x_t + h\,u_\theta(x_t, t)$$

After epoch 1 the samples are scribbles and broken strokes with plausible local texture but no global digit shape. By epoch 5 many are recognizable digits (1, 4, 5, 7 and others), but a good share are malformed, with open loops, extra strokes, or shapes that sit between two digits. By epoch 10 the digits are cleaner and more consistent, though some remain ambiguous. This is expected: the time-only model has no label, so it has to pick a digit from the noise alone, and the flow often lands between classes.

B 2.4-2.5 · Class-Conditioned Flow Matching: Training

To get better samples and control over which digit is generated, I add two more FCBlocks that embed the one-hot class vector $c$. Class features multiply the activations and time features are added: unflatten = c1 * unflatten + t1 and up1 = c2 * up1 + t2. With probability 0.1 during training the class vector is set to all zeros, so the same network also works unconditionally (needed for classifier-free guidance). Other settings match the time-only run.

class ClassConditionalUNet(nn.Module):
    def __init__(self, in_channels, num_classes, num_hiddens):
        super().__init__()
        D = num_hiddens
        self.num_classes = num_classes
        self.conv0 = ConvBlock(in_channels, D)
        self.down1 = DownBlock(D, D)
        self.down2 = DownBlock(D, 2 * D)
        self.flatten = Flatten()
        self.unflatten = Unflatten(2 * D)
        self.up1 = UpBlock(4 * D, D)
        self.up2 = UpBlock(2 * D, D)
        self.conv1 = ConvBlock(2 * D, D)
        self.out = nn.Conv2d(D, in_channels, 3, 1, 1)
        self.fc1_t, self.fc2_t = FCBlock(1, 2 * D), FCBlock(1, D)
        self.fc1_c, self.fc2_c = FCBlock(num_classes, 2 * D), FCBlock(num_classes, D)

    def forward(self, x, c, t, mask=None):
        N = x.shape[0]
        c_oh = F.one_hot(c, self.num_classes).float()
        if mask is not None:
            c_oh = c_oh * mask.view(-1, 1).float()
        t = t.view(-1, 1).float()
        t1 = self.fc1_t(t).view(N, -1, 1, 1);  t2 = self.fc2_t(t).view(N, -1, 1, 1)
        c1 = self.fc1_c(c_oh).view(N, -1, 1, 1); c2 = self.fc2_c(c_oh).view(N, -1, 1, 1)
        c0 = self.conv0(x); d1 = self.down1(c0); d2 = self.down2(d1)
        u = c1 * self.unflatten(self.flatten(d2)) + t1
        u = c2 * self.up1(torch.cat([u, d2], dim=1)) + t2
        u = self.up2(torch.cat([u, d1], dim=1))
        u = self.conv1(torch.cat([u, c0], dim=1))
        return self.out(u)

def class_fm_forward(unet, x_1, c, p_uncond, num_ts):
    unet.train()
    N = x_1.shape[0]
    t = torch.rand(N, device=x_1.device)
    x_0 = torch.randn_like(x_1)
    tt = t.view(-1, 1, 1, 1)
    x_t = (1 - tt) * x_0 + tt * x_1
    mask = (torch.rand(N, device=x_1.device) > p_uncond).float()
    return F.mse_loss(unet(x_t, c, t, mask), x_1 - x_0)

B 2.6 · Sampling from the Class-Conditioned UNet

Sampling is a 300-step Euler loop. Each step evaluates the network with the class vector and with it zeroed out, then extrapolates toward the conditional prediction with classifier-free guidance, $\gamma = 5$. Each figure shows four samples of every digit from the same seed and starting noise.

$$u = u_{uncond} + \gamma\,(u_{cond} - u_{uncond}),\quad \gamma = 5.0$$

Class conditioning with guidance is much better than the time-only model. After one epoch every column is already close to the requested digit, although several (2, 4, 5, 6, 8, 9) are wobbly or malformed. By epoch 5 the digits are mostly clean and correct, and by epoch 10 they are sharp and vary in slant and thickness across the four rows. The label removes the ambiguity the time-only model had, and $\gamma=5$ pushes each sample toward its class.

@torch.inference_mode()
def class_fm_sample(unet, c, img_wh, num_ts, guidance_scale=5.0, seed=0):
    unet.eval()
    device = next(unet.parameters()).device
    c = c.to(device)
    N = c.shape[0]
    g = torch.Generator(device=device).manual_seed(seed)
    x = torch.randn(N, 1, img_wh[0], img_wh[1], device=device, generator=g)
    ones, zeros = torch.ones(N, device=device), torch.zeros(N, device=device)
    caches = []
    for i in range(num_ts):
        t = torch.full((N,), i / num_ts, device=device)
        v_c = unet(x, c, t, ones)
        v_u = unet(x, c, t, zeros)
        x = x + (1 / num_ts) * (v_u + guidance_scale * (v_c - v_u))
        if i % max(1, num_ts // 30) == 0:
            caches.append(x.clone())
    return x, torch.stack(caches, dim=1)

B 2.6 · Removing the Learning-Rate Scheduler

To simplify training, I retrained the class-conditioned model with no scheduler. To compensate for losing the decay from $10^{-2}$ down to $10^{-3}$, I changed the following:

I used a constant learning rate of $10^{-3}$, the value the schedule decays to by the end. Starting at $10^{-2}$ with no decay would keep the updates large and noisy late in training, since every step would keep bouncing around the minimum, while $10^{-3}$ is small enough to train stably from the first step and settle by the end. The tradeoff is that early progress is slower, because the large initial steps of the scheduled run are gone.
